# Бот-конспектор лекций

Пришлите запись лекции или её расшифровку — бот сделает конспект в аккуратном оформлении: PDF или сообщениями в Telegram.

## Что умеет

- **Вход:** голосовое, аудио или видео с речью (до 20 МБ — лимит Telegram), текст сообщением или файл `.txt`.
- **Распознавание и конспект:** Gemini API. Запись отдаётся модели напрямую, текст расшифровки получается из неё же, затем модель пишет конспект по схеме. Редакторский стандарт — из скилла `notion-lecture-notes`: 8–15% от исходника, мало списков, цветные блоки.
- **Свой ключ Gemini у каждого пользователя.** Ключ присылает сам пользователь командой `/setkey`. Бот проверяет его, шифрует и хранит. Сервер не держит общий ключ, поэтому расходы и квоты у каждого свои.
- **Настройки** (команда `/settings`):
  - **Формат:** PDF-файл или сообщения Telegram в MarkdownV2. Длинный конспект режется на части по 4096 знаков.
  - **Длина:** короткий, средний или подробный.
  - **Оформление PDF:** шесть палитр или свой HEX-цвет (например `#3B82F6`).
  - **Блоки:** каждый из 10 блоков можно включить или выключить.

Команды бота: `/setkey` — прислать или заменить ключ, `/forgetkey` — удалить ключ, `/settings` — настройки.

## Ключ Gemini

Бесплатный ключ создаётся в [Google AI Studio](https://aistudio.google.com/apikey), карта не нужна. Его можно прислать сразу после `/setkey` или просто вставить в чат. Бот проверяет ключ, отправив короткий запрос к модели.

Что важно знать:

- **Данные могут использоваться.** На странице тарифов Google для бесплатного плана написано «Content used to improve our products»: содержимое запросов может использоваться для улучшения продуктов. Для учебных записей это обычно не критично. Если в записях есть персональные данные или материалы, которые нельзя передавать третьим лицам, используйте платный тариф и проверьте его условия в документации.
- **Квоты ограничены.** Лимиты (запросов в минуту и в день) зависят от модели и проекта. Актуальные значения смотрите в [AI Studio](https://aistudio.google.com/rate-limit). Когда квота исчерпана, бот пишет об этом и не падает. Сутки квоты сбрасываются в полночь по тихоокеанскому времени.
- **Модели меняются.** Старые модели (например `gemini-2.5-flash`) уже недоступны новым пользователям. Список моделей, доступных вашему ключу, и их лимиты смотрите в AI Studio, а модель задаётся в `GEMINI_MODEL`. По умолчанию стоит `gemini-3.5-flash-lite`, на ней проверена работа с живым API.
- **Хранение ключа.** Ключ шифруется Fernet. Секрет для шифрования создаётся при первом запуске в `DATA_DIR/secret.key` с правами 0600. Кто получит доступ к серверу и к этому файлу, сможет расшифровать ключи, поэтому сервер должен быть под вашим контролем.
- **Сообщение с ключом остаётся в чате.** Бот не может удалить его из личного чата, удалите его сами после отправки.

## Запуск локально

1. Создайте бота у [@BotFather](https://t.me/BotFather) и возьмите токен.
2. Установите зависимости:

   ```bash
   python -m venv .venv && . .venv/bin/activate
   pip install -r requirements.txt
   ```

   Для PDF нужны Pango и шрифты. На Debian или Ubuntu:

   ```bash
   sudo apt install libpango-1.0-0 libpangoft2-1.0-0 libharfbuzz-subset0 fonts-inter fonts-noto-color-emoji
   ```

3. Заполните `.env` и запустите:

   ```bash
   cp .env.example .env   # впишите TELEGRAM_BOT_TOKEN
   set -a; . ./.env; set +a
   python -m notes_bot
   ```

## Деплой на сервер

Самый простой способ — одна команда на сервере (Debian или Ubuntu, под root). Она клонирует ветку, спросит токен бота скрытым вводом и запустит сервис:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/roshf0rt/lecture_notes/notes-bot/deploy/bootstrap.sh)
```

Повторный запуск обновляет код и не трогает уже сохранённый `bot.env`. Ниже описаны те же шаги по отдельности.

Серверу нужен только токен бота. Ключи Gemini присылают пользователи.

Скрипт `deploy/install.sh` ставит зависимости, создаёт системного пользователя `notes-bot` и сервис `notes-bot` в systemd. Порядок такой:

1. На сервере создайте `/etc/notes-bot/bot.env` с правами 600. В нём должны быть `TELEGRAM_BOT_TOKEN=...` и `DATA_DIR=/var/lib/notes-bot`.
2. Скопируйте проект в `/opt/notes-bot`. Например, так: `git archive notes-bot | ssh root@СЕРВЕР 'mkdir -p /opt/notes-bot && tar -x -C /opt/notes-bot'`.
3. Запустите установку: `ssh root@СЕРВЕР 'bash /opt/notes-bot/deploy/install.sh'`.
4. Проверка: `systemctl status notes-bot` и `journalctl -u notes-bot -f`.

Обновление: повторите шаг 2 и выполните `systemctl restart notes-bot`.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты не ходят в сеть. Gemini для тестов подменяется локальным HTTP-сервером, который записывает запросы SDK и отдаёт заготовленные ответы. Telegram тоже заменён заглушками. Сквозной сценарий на настоящих ключах нужно проверить отдельно.

## Как устроено

```
аудио ──► Gemini (расшифровка) ──► текст ──► Gemini (JSON по схеме, только включённые блоки) ──► NoteDocument
                                                                                                  │
                                                  ┌───────────────────────────────────────────────┴───┐
                                                  ▼                                                   ▼
                                   PDF: Jinja2 HTML + WeasyPrint                  MarkdownV2: сообщения ≤ 4096
                                   (палитра темы → CSS)                           (экранирование, разбиение)
```

| Модуль | Что делает |
| --- | --- |
| `blocks.py` | Десять блоков конспекта, их порядок и цветовые роли, пресеты длины |
| `themes.py` | Палитры, проверка HEX, осветление цветов |
| `settings.py` | Настройки пользователя и их хранение в SQLite |
| `keys.py` | Зашифрованное хранение ключей Gemini по пользователям |
| `notes.py` | Модель конспекта, JSON-схема ответа для Gemini, системный промпт |
| `gemini.py` | Клиент Gemini: проверка ключа, расшифровка, конспект, загрузка больших файлов, понятные ошибки |
| `pipeline.py` | Аудио или текст → конспект → результат нужного формата |
| `render_pdf.py`, `templates/` | Вёрстка PDF |
| `render_tg.py` | MarkdownV2 и разбиение сообщений под лимит Telegram |
| `menus.py`, `bot.py` | Inline-меню настроек и хендлеры Telegram |
| `deploy/` | Unit для systemd и скрипт установки на сервер |

## Ограничения

- Telegram не отдаёт боту файлы больше 20 МБ. Длинную запись перед отправкой сожмите: моно, Opus 32 кбит/с — это примерно 14 МБ на час.
- Запросы до 12 МБ уходят в Gemini целиком. Файлы крупнее загружаются через Files API и удаляются после расшифровки.
- Gemini принимает записи до 9,5 часа в одном запросе, форматы ogg, mp3, m4a, wav, flac, aac, webm и mp4.
- Если `ALLOWED_USER_IDS` пуст, пользоваться ботом может любой, но тратить он будет квоту своего ключа. Ограничить список можно через `ALLOWED_USER_IDS`.
- Цвета применяются только к PDF. В сообщениях Telegram оформление — эмодзи и жирный шрифт.
