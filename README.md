# Бот-конспектор лекций

Пришлите запись лекции или её расшифровку — бот сделает конспект в аккуратном оформлении: PDF или сообщениями в Telegram.

## Что умеет

- **Вход:** голосовое, аудио, видео или файл (до 20 МБ через облачный Bot API Telegram, до 2 ГБ с локальным сервером, см. ниже), текст сообщением или файл `.txt`. Формат записи определяется по содержимому файла, а не по имени, поэтому AAC, M4A, OGG/Opus, MP3, WAV, FLAC, AMR, WebM, MP4 и MOV читаются даже без расширения. Видео и редкие форматы бот переводит в моно Opus через ffmpeg, файл становится в несколько раз меньше.
- **Несколько файлов сразу.** Если прислать несколько записей или файлов вместе (альбомом или подряд за пару секунд), бот покажет их список и спросит: одна лекция по частям или отдельные конспекты. Части склеиваются в порядке отправки, расшифровка каждой помечается «[Часть N из M]». Файлы, присланные, пока вопрос открыт, добавляются к нему. За раз — до 10 файлов. Если вы присылаете новые записи, пока предыдущая ещё делается, они встают в очередь и обрабатываются по порядку. В очереди у одного пользователя может быть до 5 конспектов.
- **Большие файлы до 2 ГБ.** Обычный Telegram Bot API отдаёт боту файлы только до 20 МБ. Поэтому на сервер ставится собственный Bot API сервер от Telegram (в Docker, слушает только `127.0.0.1`), и лимит становится 2 ГБ. Бот читает такие файлы прямо с диска и не загружает целиком в память; видео и длинные записи сжимаются через ffmpeg. Включается при установке, нужны `api_id` и `api_hash` с [my.telegram.org](https://my.telegram.org) (бесплатно, один раз). Без них всё работает как раньше, с лимитом 20 МБ.
- **Семестр с предметом.** `/semestr` (или `/semester`): бот показывает кнопки с предметами ваших групп и «Без раздела», вы выбираете, потом присылаете текст или файл, и конспекты по темам уходят в выбранный раздел без вопросов. Можно и сразу: `/semester`, с новой строки название предмета из вашей группы, дальше текст. Все конспекты по темам уходят в его раздел сразу, без вопросов. Если такого раздела нет среди групп, где вы состоите, бот не начинает работу. Без строки с предметом конспекты предлагаются по кнопкам, как обычно.
- **Длина.** Короткий, Средний, Подробный (по умолчанию), Максимально подробный (40–60% исходника), Без сокращений (90–100%: для готового конспекта или записи, которую нельзя резать, модель только структурирует текст и исправляет опечатки). Модели задаётся нижняя граница объёма в знаках (20% исходника для «Подробного», 40% для «Максимально подробного», 80% для «Без сокращений»), потому что проценты на словах она соблюдает плохо. В двух последних режимах материал длиннее ~20 000 знаков пишется кусками по 15 000 (по три одновременно), куски склеиваются в один конспект, а название, главная идея и дополнительные разделы делаются в конце по всему конспекту.
- **Семестр по темам.** Команда `/semester` перед текстом или в подписи к файлу делит материал по темам и делает конспект на каждую. Тексты длиннее 150 000 знаков делятся так автоматически. Модель только указывает, с какого абзаца начинается тема (абзацы пронумерованы), а текст бот режет сам, без переписывания. Темы короче 2000 знаков присоединяются к соседней, чтобы не получать конспекты в полстраницы. В режиме «Без сокращений» это правило не действует: каждая тема, которую нашла модель, получает свой конспект. Если разбиение не получилось, текст делится на равные части. Каждый конспект приходит отдельно и предлагается группе, как обычно.
- **Группа с разделами.** Бот не читает группу и не создаёт разделы. Разделы привязывает тот, кто первым написал `/bind Название предмета` внутри раздела группы: они принадлежат группе, и менять их может только он. Остальные участники группы, которые есть в боте, получают предложения: после конспекта бот спрашивает, отправить ли его в группу, раздел по предмету подбирается по словам из конспекта и отмечается ✅. Участие проверяется через Telegram, поэтому тот, кто не в группе, предложений не видит и о группе не узнаёт. В группу уходят PDF и одно короткое сообщение. `/topics` показывает группы, где вы состоите, `/unbind Название` (владелец, в группе) убирает предмет. Конспекты делаются только в личке.
- **Соглашение.** Перед первым конспектом пользователь читает пользовательское соглашение (`notes_bot/agreement.py`) и нажимает «Принимаю». Версия соглашения — хеш текста: после любой правки его принимают заново. Соглашение описывает, куда уходят записи и тексты, и что бот их не хранит.
- **PDF с текстом.** Текст из PDF бот берёт как материал для конспекта. Скан без текстового слоя он отклоняет и просит прислать текст или запись.
- **Только текст расшифровки.** В вопросе про несколько файлов есть кнопка «Только расшифровка»: бот расшифрует записи и пришлёт один .txt без конспекта. В /settings можно включить «Спрашивать про только текст»: тогда этот вопрос бот задаёт и для одной записи. Так можно часть лекции взять текстом, часть записью, а потом отправить всё .txt вместе и объединить в одну лекцию.
- **Сырая расшифровка всегда.** Из каждой записи бот сразу присылает текст расшифровки файлом .txt, ещё до написания конспекта. Если конспект не получился, текст у вас уже есть. Его можно прислать боту обратно (2–3 файла .txt подряд) и объединить в одну лекцию.
- **Распознавание и конспект:** Gemini API. Запись отдаётся модели напрямую, текст расшифровки получается из неё же, затем модель пишет конспект. Структуру она выбирает сама (см. ниже), редакторские правила взяты из скилла `notion-lecture-notes`.
- **Несколько ключей Gemini.** Каждый пользователь добавляет до 10 своих ключей (можно сразу несколько, по одному в строке). Когда у ключа кончается квота, бот переключается на следующий и не трогает «уставший» ключ минуту или до сброса дневной квоты. Неработающий ключ откладывается на час. Ключи проверяются при добавлении и хранятся зашифрованными.
- **Меню.** Постоянная клавиатура внизу чата («Настройки», «Ключи Gemini», «Помощь», у админов «Админка») и меню команд Telegram.
- **Настройки** (`/settings`):
  - **Формат:** по умолчанию «PDF и полный текст в чате»: бот присылает конспект сообщениями и PDF. Остальные варианты: «PDF и одно короткое сообщение» (полный конспект в PDF, а в чат выжимка в одно сообщение: её модель пишет по готовому конспекту, а не по всей лекции, так что лишних токенов уходит мало), «Только PDF», «Только полный текст в чате» (MarkdownV2, длинный текст режется на части по 4096 знаков), «Только одно короткое сообщение» (если результат не влезает в 4096 знаков, бот убирает разделы с конца).
  - **Длина:** короткий, средний или подробный.
  - **Язык:** как в материале или всегда по-русски.
  - **Оформление PDF:** шесть палитр или свой HEX-цвет (например `#3B82F6`).
  - **Структура конспекта не настраивается: её определяет ИИ.** Он делит лекцию на столько разделов, сколько в ней тем (от 3–4 до 15–20), и даёт каждому заголовок по сути темы. Внутри раздела ИИ выбирает элементы: таблицы (определения, сравнения, виды), нумерованные шаги, списки, выноски пяти видов (главное, оговорка, совет, пояснение, формула), сворачиваемые кейсы, чек-листы, подзаголовки. Длина «Подробный» (по умолчанию) требует максимальной полноты: все темы, определения, имена, цифры, кейсы, задания преподавателя.
  - **Дополнения** (в `/settings`, по умолчанию выключены): «Что запомнить» (чек-лист), «Вопросы для самопроверки», «Термины и определения» (таблица). Выбранные разделы ИИ добавляет в конец конспекта. В режиме «Одно короткое сообщение» они не добавляются.
  - **Расшифровка файлом:** вместе с конспектом присылать полный текст записи в `.txt`.
- **Админ-панель** (`/admin`): статистика (пользователи, конспекты, ошибки, самые активные), список пользователей с карточками, блокировка, выдача прав админа, режим доступа (всем или по белому списку), выбор модели Gemini с проверкой, общие ключи для пользователей без своего ключа, рассылка любого сообщения всем, лимит конспектов в сутки, уведомления о новых пользователях, режим обслуживания.
- **Премиум-эмодзи** из пака [Telegram iOS Icons](https://emoji.wivvi.net) в сообщениях, кнопках и заголовках блоков. Кнопки подсвечены цветом (Bot API 9.4). Иконки видны, только если у владельца бота есть Telegram Premium; в админке их можно выключить, а если Telegram откажет, бот сам отправит обычные эмодзи.

**Ключи поставщика-посредника.** Бот принимает и ключи вида `sk-cvc-…` (OpenAI-совместимый API `api.aikeysforyou.com`). Это не Google: записи и тексты уходят стороннему сервису, а условия хранения данных он не публикует. Бот прямо пишет об этом при добавлении такого ключа. Модель для них задаётся `GATEWAY_MODEL` (по умолчанию `gemini-3.5-flash`). Запросы к одному такому ключу идут через общий ограничитель: не больше 3 одновременных и 60 в минуту (поставщик разрешает 6 и 120), между кусками одной записи пауза 3 секунды. Чтобы тратить меньше токенов, из кусков перед отправкой вырезаются паузы длиннее секунды (речь не меняется), а на проблемный кусок делается не больше двух попыток.

**Речь через посредника не распознаётся.** Проверено на живых записях: шлюз не передаёт звук модели. Она либо отвечает просьбами «прикрепите файл», либо выдумывает правдоподобный текст другой лекции (запись про событийный маркетинг превратилась в «разложение дробей»). Выдумку отличить от настоящей расшифровки нельзя, поэтому записи бот отдаёт только ключам Google. Если у пользователя только ключ посредника, бот просит добавить ключ Google или прислать текст. Ключ посредника работает для конспекта по готовому тексту. Куски, где модель просит прислать файл, бот всё равно отбраковывает.

Команды: `/start`, `/settings`, `/keys`, `/help`, у админов ещё `/admin`. Старые `/setkey` и `/forgetkey` тоже работают.

## Ключ Gemini

Бесплатный ключ создаётся в [Google AI Studio](https://aistudio.google.com/apikey), карта не нужна. Его достаточно вставить в чат или добавить через «Ключи Gemini». Бот проверяет ключ, отправив короткий запрос к модели.

Что важно знать:

- **Данные могут использоваться.** На странице тарифов Google для бесплатного плана написано «Content used to improve our products»: содержимое запросов может использоваться для улучшения продуктов. Для учебных записей это обычно не критично. Если в записях есть персональные данные или материалы, которые нельзя передавать третьим лицам, используйте платный тариф и проверьте его условия в документации.
- **Несколько ключей помогают, только если они из разных проектов.** Квота бесплатного плана считается на проект Google Cloud, а не на ключ. Два ключа из одного проекта делят одну квоту. Для запаса создавайте ключи в разных проектах или аккаунтах.
- **Квоты ограничены.** Лимиты (запросов в минуту и в день) зависят от модели и проекта. Актуальные значения смотрите в [AI Studio](https://aistudio.google.com/rate-limit). Когда квота исчерпана, бот пишет об этом и не падает. Сутки квоты сбрасываются в полночь по тихоокеанскому времени.
- **Модели меняются.** Старые модели (например `gemini-2.5-flash`) уже недоступны новым пользователям. Список моделей, доступных вашему ключу, и их лимиты смотрите в AI Studio, а модель задаётся в `GEMINI_MODEL` и меняется в админке без перезапуска. По умолчанию стоит `gemini-3.5-flash-lite`, на ней проверена работа с живым API.
- **Хранение ключа.** Ключ шифруется Fernet. Секрет для шифрования создаётся при первом запуске в `DATA_DIR/secret.key` с правами 0600. Кто получит доступ к серверу и к этому файлу, сможет расшифровать ключи, поэтому сервер должен быть под вашим контролем.
- **Сообщение с ключом остаётся в чате.** Бот не может удалить его из личного чата, удалите его сами после отправки.

## Запуск локально

1. Создайте бота у [@BotFather](https://t.me/BotFather) и возьмите токен.
2. Установите зависимости:

   ```bash
   python -m venv .venv && . .venv/bin/activate
   pip install -r requirements.txt
   ```

   Для PDF нужны Pango и шрифты. На Debian или Ubuntu:

   ```bash
   sudo apt install libpango-1.0-0 libpangoft2-1.0-0 libharfbuzz-subset0 fonts-inter fonts-noto-color-emoji
   ```

3. Заполните `.env` и запустите:

   ```bash
   cp .env.example .env   # впишите TELEGRAM_BOT_TOKEN
   set -a; . ./.env; set +a
   python -m notes_bot
   ```

## Деплой на сервер

Самый простой способ — одна команда на сервере (Debian или Ubuntu, под root). Она клонирует ветку, спросит токен бота скрытым вводом и ваш Telegram ID (вы станете админом), поставит зависимости и запустит сервис:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/roshf0rt/lecture_notes/notes-bot/deploy/bootstrap.sh)
```

**Автообновление.** Раз в 10 минут сервер проверяет ветку `notes-bot`. Если там появился новый код, он подтягивается, обновляются зависимости и перезапускается бот (`notes-bot-update.timer`, скрипт `deploy/update.sh`). Перезапуск прерывает конспект, который делается в этот момент: пользователь получит ошибку и пришлёт запись заново. Бот пишет число идущих конспектов в `active.jobs`, и скрипт не перезапускает его, пока оно не ноль (и пока идёт конвертация записи ffmpeg). Отложенное обновление применится само при следующей проверке.

**Обновление по кнопке.** В админке есть кнопка «Обновить бота из git». Бот не может заменить свой код сам, поэтому он оставляет запрос в `/var/lib/notes-bot/update.request`, а root-сервис `notes-bot-update.path` запускает `deploy/update.sh`. Скрипт обновляет бота и присылает админу результат: «уже последний коммит», «обновлено» или «отложено, идёт конвертация».

**Обновление вручную** — та же команда. Она подтянет новый код, оставит `bot.env` и данные, перезапустит бота. Если в `bot.env` ещё нет `ADMIN_IDS`, она спросит ваш ID.

**Файлы больше 20 МБ.** Скрипт спросит `api_id` и `api_hash`: откройте https://my.telegram.org, войдите по номеру телефона, выберите «API development tools», создайте приложение (название любое) и скопируйте оба значения. Скрипт поставит Docker, запустит локальный Bot API сервер (`notes-bot-api`) и один раз «выведет» бота из облачного API Telegram (`logOut`). Чтобы включить позже, запустите скрипт снова: он спросит значения, если они не сохранены. Записи, которые сервер скачал, удаляются через 3 часа (`notes-bot-cleanup.timer`).

Локальный сервер пишет скачанные файлы с правами 0600 от своего пользователя, поэтому сервису бота выдаётся право чтения `CAP_DAC_READ_SEARCH`. Это право только на чтение: писать и удалять бот не может, а каталоги `/root`, `/home`, `/etc/ssh`, `/etc/shadow` и `/etc/notes-bot` для него закрыты.

**Как стать админом.** Свой ID показывает @userinfobot, а ещё бот: напишите ему `/admin`, и он пришлёт готовую команду для сервера. Вручную: допишите `ADMIN_IDS=ВАШ_ID` в `/etc/notes-bot/bot.env` и выполните `systemctl restart notes-bot`. Следующих админов можно назначать прямо в админке.

Серверу нужен только токен бота. Ключи Gemini присылают пользователи (или админ добавляет общие).

Скрипт `deploy/install.sh` ставит зависимости (включая ffmpeg), создаёт системного пользователя `notes-bot` и сервис `notes-bot` в systemd. По шагам:

1. На сервере создайте `/etc/notes-bot/bot.env` с правами 600. В нём должны быть `TELEGRAM_BOT_TOKEN=...`, `DATA_DIR=/var/lib/notes-bot` и `ADMIN_IDS=...`.
2. Скопируйте проект в `/opt/notes-bot`. Например, так: `git archive notes-bot | ssh root@СЕРВЕР 'mkdir -p /opt/notes-bot && tar -x -C /opt/notes-bot'`.
3. Запустите установку: `ssh root@СЕРВЕР 'bash /opt/notes-bot/deploy/install.sh'`.
4. Проверка: `systemctl status notes-bot` и `journalctl -u notes-bot -f`.

Данные лежат в `/var/lib/notes-bot`: `settings.sqlite3` (настройки), `keys.sqlite3` и `secret.key` (зашифрованные ключи), `bot.sqlite3` (пользователи, статистика, параметры админки). Ключи из первой версии бота переносятся автоматически.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты не ходят в сеть. Gemini для тестов подменяется локальным HTTP-сервером, который записывает запросы SDK и отдаёт заготовленные ответы. Telegram тоже заменён заглушками. Сквозной сценарий на настоящих ключах нужно проверить отдельно.

## Как устроено

```
аудио ──► Gemini (расшифровка) ──► текст ──► Gemini (JSON: название, главная идея, разделы из элементов) ──► NoteDocument
                                                                                                  │
                                                  ┌───────────────────────────────────────────────┴───┐
                                                  ▼                                                   ▼
                                   PDF: Jinja2 HTML + WeasyPrint                  MarkdownV2: сообщения ≤ 4096
                                   (палитра темы → CSS)                           (экранирование, разбиение)
```

| Модуль | Что делает |
| --- | --- |
| `blocks.py` | Длины конспекта и их указания для ИИ |
| `themes.py` | Палитры, проверка HEX, осветление цветов |
| `settings.py` | Настройки пользователя и их хранение в SQLite |
| `keys.py` | Зашифрованное хранение ключей Gemini: несколько у пользователя плюс общие |

## Ограничения

- Без локального Bot API сервера Telegram не отдаёт боту файлы больше 20 МБ. Тогда длинную запись перед отправкой сожмите: моно, Opus 24 кбит/с — это примерно 11 МБ на час. С локальным сервером лимит 2 ГБ.
- Запросы до 12 МБ уходят в Gemini целиком. Файлы крупнее загружаются через Files API и удаляются после расшифровки.
- Gemini принимает записи до 9,5 часа в одном запросе. Без ffmpeg на сервере видео и редкие форматы (AMR, WMA, MKV) не читаются, остальные уходят как есть.
- По умолчанию пользоваться ботом может любой, но тратит он квоту своего ключа. Закрыть доступ и вести белый список можно в админке.
- Одновременно делается не больше `MAX_PARALLEL_JOBS` конспектов (по умолчанию 3), остальные ждут в очереди.
- Цвета применяются только к PDF. В сообщениях Telegram оформление — эмодзи и жирный шрифт.
